Je veux automatiser la clôture du questionnaire de voyage : quand tous les participants ont répondu, les suggestions doivent être générées automatiquement, sans que l'organisateur ait à cliquer sur "Regénérer".

Voici les changements à faire :

1. Dans `src/lib/krew/trip-service.ts` : extraire toute la logique de génération de recommandations (qui est actuellement dans le handler `generateRecommendations` de `src/lib/trips.functions.ts`) dans une nouvelle fonction exportée `generateRecommendationsForTrip(supabase, tripId)`. Elle doit faire exactement ce que fait `generateRecommendations` aujourd'hui : charger `trips` et `trip_preferences`, agréger les réponses via `aggregateParticipantPreferences`, construire le `ScoringContext` avec `buildScoringContext`, charger le catalogue via `loadTravelCatalog`, générer les propositions avec `buildProposals`, supprimer les anciennes `recommendations` du trip, insérer les nouvelles, et passer le statut du trip à `"propositions"`. Retourne `{ count: rows.length }`.

2. Dans `src/lib/trips.functions.ts` : simplifier le handler `generateRecommendations` pour qu'il appelle juste `generateRecommendationsForTrip(context.supabase, data.tripId)` et retourne son résultat. Nettoyer les imports devenus inutiles (`buildProposals`, `loadTravelCatalog`, `buildScoringContext`, `serializeProposal`, `aggregateParticipantPreferences`) et importer `generateRecommendationsForTrip` depuis `@/lib/krew/trip-service`.

3. Dans `src/lib/participant-preferences.functions.ts` : après l'upsert dans `trip_participant_preferences` du handler `submitParticipantPreferences`, calculer la progression : `total` = nombre de lignes dans `trip_participants` pour ce trip, `answered` = nombre d'`user_id` distincts dans `trip_participant_preferences` pour ce trip. Si `total > 0` et `answered >= total`, appeler `generateRecommendationsForTrip(supabase, data.tripId)` dans un try/catch (ne jamais faire échouer la soumission si la génération plante) et mettre `autoGenerated = true`. Le handler doit retourner `{ ok: true, progress: { answered, total }, autoGenerated }` au lieu de juste `{ ok: true }`. Importer `generateRecommendationsForTrip` depuis `@/lib/krew/trip-service`.

4. Dans `src/routes/_authenticated/trips.$tripId.questionnaire.tsx`, fonction `handleSubmit` : récupérer le résultat de `submit(...)` dans une variable `res`. Si `res.autoGenerated` est vrai, afficher un toast de succès "Tout le monde a répondu — les suggestions Krew sont prêtes !". Sinon, afficher "Tes réponses sont enregistrées ! (X/Y ont répondu)" en utilisant `res.progress`.

5. Dans `src/routes/_authenticated/trips.$tripId.tsx` : importer `getParticipantsProgress` depuis `@/lib/participant-preferences.functions`, l'appeler avec `useServerFn` + `useQuery` (clé `["trip-progress", tripId]`), et invalider cette query en plus de la query principale dans la fonction `refresh`. Afficher à côté du bouton "Répondre à mon questionnaire" un texte "X/Y ont répondu au questionnaire", avec un petit "· complet 🎉" quand `answered >= total`.

Le bouton "Regénérer" existant doit continuer à fonctionner exactement comme avant (génération manuelle à tout moment, même avec des réponses partielles) — ne rien changer à son comportement, juste à ce qu'il appelle en interne.
